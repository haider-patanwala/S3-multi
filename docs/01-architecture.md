# Architecture

## Stack

React 19 · TypeScript · Vite 7 · TanStack Router (file-based, code-split) ·
TanStack Query · TanStack Virtual · AWS SDK v3 · Tailwind CSS v4 · Biome.

## Layers

```
routes/          UI + mutations. Owns local component state and user feedback.
components/ui/   Presentational primitives (shadcn-style, Base UI underneath).
lib/             All I/O and domain logic. No React.
  ├─ s3.ts           every S3/R2 API call
  ├─ cdn.ts          CloudFront + Cloudflare purge
  ├─ providers.ts    vault read/write (encrypt on the way in)
  ├─ crypto.ts       AES-GCM wrap/unwrap
  ├─ idb.ts          raw IndexedDB access
  ├─ transfers.ts    transfer history persistence
  ├─ query-options.ts TanStack Query key + fetcher definitions
  ├─ types.ts        shared domain types
  └─ utils.ts        formatting, path math, content-type guesses
```

**Rule:** `lib/` never imports from `routes/` or `components/`. A route may call
`lib/` freely. Domain logic that lives in a route (rather than `lib/`) is
misplaced — this is how the save bug hid.

## Boot

`src/main.tsx` → creates one `QueryClient` and one router, mounts
`RouterProvider` inside `QueryClientProvider`. The `queryClient` is threaded into
router context via `createRootRouteWithContext` in `src/routes/__root.tsx`.
Devtools render only when `import.meta.env.VITE_NODE_ENV === "development"`
(set in `.env`).

## Routes

| Path | File | Purpose |
|---|---|---|
| `/` | `src/routes/index.tsx` | Redirects to `/browse` |
| `/browse` | `src/routes/browse.tsx` | The main workspace: listing, preview, editor, purge dialog |
| `/providers` | `src/routes/providers.tsx` | Provider CRUD and connection test |
| `/transfers` | `src/routes/transfers.tsx` | Transfer history |
| `/help` | `src/routes/help.tsx` | User-facing help |

`src/routeTree.gen.ts` is generated by `@tanstack/router-plugin` — never hand-edit it.

`/browse` search params are validated by a Zod schema (`searchSchema` in
`src/routes/browse.tsx`): `providerId`, `bucket`, `prefix`, `view`. The URL is the
source of truth for *where you are*; effects reconcile it toward the resolved
provider/bucket. This makes locations shareable and reload-safe.

## State ownership

| State | Lives in | Notes |
|---|---|---|
| Location (provider/bucket/prefix/view) | URL search params | Zod-validated |
| Server data (buckets, objects, transfers, providers) | TanStack Query | Keys in `src/lib/query-options.ts` |
| Durable data (credentials, transfer history, active provider, recent bucket) | IndexedDB | See [provider-vault](02-provider-vault.md) |
| Ephemeral UI (open dialogs, editor buffer, status message) | `useState` in the route | |

### Query keys

Defined centrally in `src/lib/query-options.ts` so invalidation is predictable:

- `["providers"]`, `["providers", "active"]`, `["providers", id, "recent-bucket"]`
- `["buckets", providerId]`
- `["objects", providerId, bucket, prefix, search]`
- `["transfers"]`

Mutations invalidate by prefix, e.g. `["objects", providerId, bucket]` refreshes
every prefix/search combination in that bucket.

## Data flow — a write

```
user action (route)
  → useMutation
    → lib/s3.ts  ── signed request ──▶ S3 / R2
    → lib/cdn.ts ── purge request  ──▶ CloudFront / Cloudflare
  → status message rendered  (never swallowed)
  → queryClient.invalidateQueries  → list refetches
```

## Build-time pieces

`vite.config.js` holds three plugins (Tailwind, TanStack Router, React) and the
`@` → `src` alias. Nothing else — no dev proxy, no server middleware. The app is a
pure static bundle, which is why anything a browser cannot call directly (such as
Cloudflare's purge API) is surfaced as a command to run rather than automated. See
[cdn-purge](07-cdn-purge.md).
